# Director Planner 时长约束修复

审计基线：2026-10-14 拉取的 `origin/main`，`c5a89ca`。
已检查合并的 PR #2、#3、#5、#6、#7、#9；未合并草稿 PR #8 不作为本次基线。

## 根因

1. `Qwen38LongVideoDirectorPlanner.plan()` 已根据实际输入（包括外接总时长）调用
   `_director_duration_schedule()`，得到合法总时长、组数和初始时长表。
2. Structure Pass 却只使用组数与总时长，提示模型自由选择 `<4-15>` 时长。
3. `_segments_from_structure_cards()` 先调用 `_parse_duration_token()`；遇到第 9 段 21 秒，
   当场抛错，之后的对白再分配、coverage allocations 和总时长 rebalance 均没有执行机会。
4. 两次结构尝试确实带回了异常文字，但每次都要求重新输出全部结构卡，无法保证只修复错误分段。
5. 原始舍入还存在另一条失败路径：180.123 秒 / 45 段，前 44 段各舍入为 4.003 秒，
   末段补差得到 3.991 秒。7 秒 / 平均 4 秒也会错误地申请两段，各不足 4 秒。

## 修复

- 推理前锁定宿主时长表；有可解析剧情节拍时，复用 coverage 分配形成非均匀时长。
  无节拍估计时使用初始均分。Structure Pass 收到完整表和首段的具体时长。
- 实际 per-segment 路径读取锁定表，不允许模型的合法数字重新覆盖它。
  保留 legacy single-shot 路径和旧的直接转换行为，避免扩大兼容性变更。
- 用毫秒整数分配余数；组数不能超过总时长允许的 4 秒下限。
- 将大于 15 秒的卡片视为内容溢出信号，先检查全片预算能否容纳，再局部拆分。
  21 秒分成 10.5 + 10.5；16 秒分成 8 + 8，绝不产生 1 秒尾段。
- 拆分模型只能返回 BEAT、DIALOGUE 连续原文切片以及中间衔接状态。
  校验切片完整、连续、无重复、无乱序；继承素材、原起始连续性、原最终 HANDOFF。
  中间子段设置连续；之后的原卡片衔接标志不变。coverage 分组映射随拆分扩展。
- 对白使用已有的中英文字量估计检查；若调走时长会使其他卡片对白超预算，也拒绝修复。
- 正常计划无额外模型调用；异常卡片最多两次局部尝试。格式/组数错误保留原全局两次尝试。
  未提高 H3 最大时长，未增加全局重试次数，未跳过最终边界校验。
- 异常保存原始输出；修复失败提供原分段编号、时长、原因及诊断文件路径。

## 对比

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 长规划第 9 段 21 秒 | 解析即抛错，全部结构重试 | 预算可行时仅拆该卡为两段 10.5 秒 |
| 多卡 21 秒、16 秒 | 首个错误终止 | 分别拆修，保留其他卡内容并保持总时长 |
| 模型将合法宿主 10 秒改为 12 秒 | 使用模型数字再再分配 | 使用宿主 10 秒契约 |
| 180.123 秒、45 段 | 末段可能 3.991 秒 | 毫秒余数分配，各段合法 |
| 260 秒 | 拒绝 | 仍明确拒绝，不压缩为 240 秒 |
| 无法容纳或切片有丢失 | 重新生成整份结构 | 带诊断拒绝，不截断剧情 |

## 限制与部署

- 测试使用模拟 completion，不加载 27B GGUF，不执行视频生成。尚未进行真实模型端到端验证。
- 原文校验能保证局部拆修不丢失/重复/乱序，但不能证明 LLM 首次结构输出已涵盖 brief 的全部语义，
  也不能自动证明中间 HANDOFF 与动作对白的语义关系正确，仍需预览。
- PR #9 的未修复结构关键对白缺失仍是原有软警告；发生局部修复后会再次检查并拒绝缺失关键对白的结果。
- 语速是估计，不是生成音频的实测时长。总预算确实不足时会拒绝，不承诺任何剧情都能装入 240 秒。
- 部分模型可能无法严格返回连续原文切片；两次失败后保留诊断并停止。
- 本次只修改提示词插件代码与文档，不依赖修改导演台。下游 group 与 prompt 输出结构不变；
  refine 调试记录新增时长表、局部修复数和诊断路径。
- 更新运行中的插件后需重启 ComfyUI 并重新 Preview，不应释放更新前缓存的旧规划。
